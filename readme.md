# MUT Transport Bot

Чат-бот для информирования пассажиров о задержках транспорта. Отвечает на вопросы на естественном языке, использует оперативный реестр (SQLite/мок) для точных фактов и векторную базу знаний (Qdrant) для семантического поиска.

---

## Стек

- **Python 3.12** — язык разработки
- **LangChain / LangGraph** — оркестрация агента (граф состояний, middleware)
- **Qdrant** — векторная БД для семантического поиска (RAG, база знаний)
- **HuggingFace Embeddings** (`intfloat/multilingual-e5-small`) — локальные эмбеддинги (размерность 384)
- **OpenRouter (Qwen)** — LLM для формулировки ответов (с абстракцией под DeepSeek)
- **Docker** — контейнеризация Qdrant
- **SQLite** — реляционная БД для точных фактов (в разработке, пока мок)

---

## Архитектура: две базы — две роли

| | **SQLite (реляционная)** | **Qdrant (векторная)** |
|---|---|---|
| **Что хранит** | Точные факты: `route`, `transport`, `status`, `start_time` | Смысловые эмбеддинги текстов: FAQ, исторические инциденты |
| **Зачем** | Ответить на «есть ли **активная** задержка на маршруте 5?» | Ответить на «какие причины задержек?» |
| **Кто заполняет** | Диспетчер через `confirm_incident` | Скрипт `seed_qdrant.py` (один раз) |
| **Когда обновляется** | При каждом новом инциденте | При обновлении базы знаний (редко) |

**Важно:** мы не дублируем каждый инцидент в Qdrant, чтобы избежать рассинхронизации. Агент сначала проверяет SQLite (оперативный реестр), потом Qdrant (база знаний).

## Быстрый старт

### 1. Клонировать репозиторий

```bash
git clone https://github.com/ТВОЙ_НИК/mut-transport-bot.git
cd mut-transport-bot
```

### 2. Установить зависимости

```bash
pip install -r requirements.txt
```

### 3. Создать `.env`

```env
OPENROUTER_API_KEY=твой_ключ_с_openrouter
```

> **Важно:** `.env` не коммитится в git (см. `.gitignore`).

### 4. Запустить Qdrant в Docker

```bash
docker compose up -d
```

Проверка: `docker ps` — контейнер `qdrant` должен быть `Up`.

### 5. Загрузить базу знаний в Qdrant

```bash
python seed_qdrant.py
```

### 6. Запустить агента

```bash
python agent.py
```

### 7. Сквозной тест (диспетчер → бот)

```bash
python test_e2e.py
```

## Как это работает

### Сценарий 1: пассажир спрашивает про конкретный маршрут

1. Пассажир: «Почему трамвай 5 стоит на Ленина?»
2. Агент вызывает `get_active_incidents(5, "tram")` → SQLite (мок) → точный статус.
3. Если нужно — дополнительно `search_incidents` → Qdrant → подробности.
4. LLM формулирует ответ на основе данных.

### Сценарий 2: пассажир спрашивает про место (без маршрута)

1. Пассажир: «Что случилось на Ленина?»
2. Агент вызывает `get_all_active_incidents()` → SQLite (мок) → все активные инциденты.
3. Если есть инцидент на Ленина — отвечает по нему (актуальные данные).
4. Если нет — вызывает `search_incidents("Ленина")` → Qdrant → база знаний.

### Сценарий 3: диспетчер вводит инцидент

1. Диспетчер: «ДТП на Ленина, трамвай 5 стоит».
2. `process_event` (LLM + Pydantic) разбирает текст в `ParsedEvent`.
3. `confirm_incident` сохраняет инцидент в SQLite (мок).
4. Агент видит новый инцидент и отвечает пассажирам.

## Инструменты агента

| Инструмент | Когда вызывать | Источник |
|---|---|---|
| `get_active_incidents(route, transport)` | Конкретный маршрут и тип | SQLite (мок) |
| `get_all_active_incidents()` | Общая картина, все инциденты | SQLite (мок) |
| `search_incidents(query)` | Причина, место, FAQ, общие вопросы | Qdrant |

## Примечания

- На Windows с VPN добавлен `NO_PROXY=localhost,127.0.0.1`, чтобы Qdrant-клиент ходил напрямую, а OpenRouter — через VPN.
- Эмбеддинги локальные, не зависят от внешних API.
- LLM абстрагирована: замена OpenRouter на DeepSeek — смена `base_url` и модели в `settings.py`.
- `recursion_limit=8` ограничивает количество шагов агента (защита от зацикливания).
- Логи агента пишутся в `agent.log` (middleware в `agent_logger.py`).
